# FORM Character — Unity renderer

Unity 6000.6.2f1 / URP. Open `FormCharacter` in Unity Hub. This independent project leaves the tutorial project untouched. The local Unity CLI Pipeline connection is installed.

`Assets/Scenes/FormCharacter.unity` is generated by `FormBuild.Setup()`. `FormCharacter` receives procedural mesh recipes from React via Unity's JavaScript `SendMessage` bridge. The character model in `src/character/geometry.js` is shared with the immediate web previews; customization remains available while Unity loads. No player accounts or Unity cloud services are required.

The scene uses an original toon shader, parametric body meshes, configurable hair/clothes, articulated arms and meal/workout emotes. It is an original prototype rather than Xenoverse character assets or a console-quality rigged production model.

## Rebuild

1. Open `unity/FormCharacter` and wait for compilation. Runtime sources are in `Assets/Form`; the build command is `Assets/Editor/FormBuild.cs`. `tools/` contains the initial source copies used to import through the live Editor.
2. From the repository root, with the Unity CLI installed:

```sh
unity command eval --project-path "$PWD/unity/FormCharacter" --caller plugin --skill unity-cli --code 'FormBuild.Build(); return "Build queued";' --format json
```

3. The queue waits for script compilation and asset imports before building, and survives a script reload. Wait for `unity/build-status.txt` to say `Succeeded`. Then:

```sh
node unity/tools/publish.mjs
npm run build
```

The build goes to `public/unity/`, ignored by Git. The manifest connects the generated loader, WASM, framework, and data filenames. Vite copies these to `dist/unity` for production. WebGL build support must be installed for this Editor version. The first IL2CPP build takes several minutes; later builds use Unity's cache.

`?renderer=web` forces the lightweight Three.js renderer, useful for development or constrained devices. A Unity load failure also keeps that renderer available. The main viewer displays which renderer is active. Customizer and celebration previews use the same mesh recipe with Three.js so multiple Unity engines do not compete for device memory.

Canonical profile and workout measurements remain kg/cm/liters regardless of display units. Recipes and logs stay local; the Unity bridge does not send them to Unity Cloud.

The runtime disables Unity's global keyboard capture, and React hosts Unity in a same-origin embedded frame to isolate engine event listeners from meal and measurement inputs; see Unity's [Web keyboard capture documentation](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/WebGLInput-captureAllKeyboardInput.html).
